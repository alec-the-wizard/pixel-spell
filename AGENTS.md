# AGENTS.md

Guidance for AI coding agents working on Pixel Spell.

## What this project is

Pixel Spell is a client-only pixel art editor built with Svelte 5, Vite, TypeScript, Tailwind CSS 4, shadcn-svelte, bits-ui, and Lucide icons. It supports layered sprites, frame-by-frame animation, PNG export, and portable project files.

There is no backend, database, or server-side rendering. Everything runs in the browser.

## Commands

```bash
npm run dev      # Vite dev server
npm run check    # svelte-check + tsc; must pass before finishing
npm run build    # production build
npm run preview  # preview the production build
```

Use `npm run check` after any non-trivial change. Run `npm run build` before declaring work complete.

## State and reactivity

- The singleton is exported as `editor` from `editor.svelte.ts`. **Do not rename it back to `state`**: a local binding named `state` conflicts with the `$state` rune and breaks compilation.
- `editor.doc` is a `$state` proxy, so layer names, visibility, opacity, frame arrays, etc. are reactive.
- Pixel data lives in `Uint32Array` cels. Typed arrays are **not** deeply proxied, so mutating pixels will not trigger a re-render on its own. Call `editor.touch()` (increments `revision`) after changing pixel data, or increment `editor.revision` after structural changes that do not already do so.
- Any mutation that should be undoable must record history **before** the change: `pushHistoryCel`/`pushHistoryCels` for pixel edits and `pushHistory` for structural edits. Pixel edits, layer/frame add/delete/duplicate/reorder, clear layer/frame are undoable. Selection, visibility, opacity, and renaming are not.
- `editor.revision` is the render invalidation signal. `CanvasStage`, `Preview`, and the active `CelThumb` read it inside `$effect`.
- `editor.structureRevision` changes only when layers/frames are added, removed, reordered, or restored by undo/redo or a project switch. `CelThumb` redraws all cells on `structureRevision` but only the active cell on `revision`.
- `editor.layerAppearanceRevision` changes when layer visibility or opacity changes. The onion-skin effect uses it instead of `revision` so painting the active frame does not recomposite neighboring frames on every brush stamp.
- `editor.frameSelection` holds selected frame ids and always includes the active frame except during playback. `editor.selectedFrameIndices` returns them in timeline order. Frame operations (copy, paste, duplicate, reorder, delete, duration, tag) operate on that selection.
- `editor.layerSelection` holds the selected layer ids and always includes `activeLayerId`. It is a timeline layer selection paired with the frame selection, **not** a grouping of individual cels. `editor.selectCel`, `extendCelSelection`, and `selectCelRange` update both axes and make the last cel active; `selectLayer` and `extendLayerSelection` handle row-header selection. Ctrl/Cmd-click does not toggle timeline selection, so both axes stay contiguous. `#setActiveLayer` resets the selection whenever a layer is added, imported, deleted, or ungrouped.
- `editor.linkSelectedCels()` and `editor.unlinkSelectedCels()` operate on the rectangular cel selection. Link shares one buffer across every selected frame on each selected layer, using the active frame as the source; it requires at least two frames (`editor.canLinkSelectedCels`). Unlink gives each linked selected cel its own buffer and also works for a single cel (`editor.canUnlinkSelectedCels`). Both are undoable.
- `Frame.duration` is optional; missing means `1000 / doc.fps`. `doc.animationMode` is optional (`forward` when missing) and `doc.animationLoop` is optional (`true` when missing). Use `frameDurationMs`, `normalizeAnimationMode`, and `animationSequence` from `doc.ts` instead of duplicating the fallback logic.
- The animation range is the frame selection: one selected frame means the whole timeline, two or more selected frames mean exactly those frames in timeline order. Playback and animation/video export both use `editor.animationFrameIndices`.
- The Effects dialogs run pure filters from `filters.ts` through `editor.previewEffect(scope, transform)` and `editor.applyEffect(scope, transform)`. The scope is `active-cel` or `visible-layers`; both skip reference, hidden, and locked layers, and only the active frame is affected. Filters honour the active selection mask, previews composite the modified clone through `compositeFrame`, and applying writes filtered pixels into the existing buffers (so linked cels stay linked) behind one `pushHistoryCels` entry.
- Gradient map is both a destructive filter and a group effect. `gradient-map.ts` owns stop normalization, LUT sampling, RGB/OKLab interpolation, luminance/average brightness, inversion, and the CSS preview string; keep it pure and shared instead of duplicating math in dialogs. `GradientMapDialog.svelte` uses `editor.previewEffect`/`applyEffect` like the other Effects dialogs, while `GradientMapEditor.svelte` is the shared stop editor. Stops may share a position to create a hard edge. Alpha is always preserved and transparent pixels are never painted.
- Grayscale is also both a destructive filter and a group effect, but it is a conversion rather than a document color mode. `grayscale.ts` owns the 1/2/4/8-bit ramp quantization and perceptual luminance (`0.2126·R + 0.7152·G + 0.0722·B`); never substitute an RGB average. `GrayscaleDialog.svelte` applies it through `previewEffect`/`applyEffect`, the `grayscale` group effect uses `bits`, and `Grayscale` blocks appear in the timeline effect menu. The preview window's grayscale toggle is presentation-only (8-bit) and the workspace-level `previewGrayscale`/`previewZoom` state never touches cels, history, or project files. PNG image and sheet export opt into a true 8-bit grayscale file through `grayscale-png.ts`; other formats ignore the option.
- Group effect blocks are the non-destructive counterpart. `Layer.effects` on a group node stores an ordered `GroupEffect[]`; `group-effects.ts` owns defaults, validation, and the pure chain runner. `compositeFrame` applies the stack to the group's composited buffer before the group's opacity/blend/clipping, so inner groups run before outer groups and effects appear in viewport, preview, and export. `compositePixel` falls back to a full composite when any enabled effect exists because neighborhood filters cannot run per pixel. Add/remove/reorder/enable/option edits and baking are undoable via `pushHistory`; every change bumps `structureRevision` and `revision`. `editor.bakeGroupEffect` writes the filter into every visible non-reference paint layer inside the group across all frames (one transform per distinct buffer, preserving linked cels), then removes the block. Group effects are workspace-independent and serialized in project metadata, not in cels.
- Onion skin state (`onionEnabled`, range, opacity, previous/next toggle, tints) is workspace-wide and does not touch the document, history, or dirty flag. `editor.onionSkins` returns the neighboring frame indices and hides them during playback.
- Custom brushes and dither patterns are workspace libraries stored in `localStorage` (`pixel-spell-brushes`, `pixel-spell-dither-patterns`), like palettes. They are never written to project files, history, or autosaves. Built-ins live in code; only custom 1-bit masks are persisted. `editor.brushSize`, `brushOpacity`, `showBrushPreview`, `ditherEnabledByTool`, `ditherOffsetX/Y`, and `ditherAlign` are workspace state, not document state.
- `stampMask` in `draw.ts` is the generic brush path: it takes a `PixelMask`, symmetry, selection clip, alpha lock, ink opacity, and an optional `DitherSampler`. `paintBrush` remains a cached square-mask wrapper for compatibility. `fillPixels` accepts an optional dither sampler as its final argument. `CanvasStage` snapshots the active brush mask, opacity, and dither sampler on pointer down so a whole gesture stays consistent; apply the same snapshot in plain strokes, shape outlines, curve previews, and pixel-perfect replays.
- Live dither ink and the destructive dither filter are deliberately separate. The per-tool toggle lives in `DitherSettings.svelte`; `Effects → Dither…` opens `DitherDialog.svelte` and uses the pure `ditherPixels` filter through `editor.previewEffect`/`applyEffect`. Do not route cursor painting through the destructive filter, and do not make the filter mutate in place.
- `MaskThumb.svelte` and `MaskGridEditor.svelte` render 1-bit masks. Typed arrays are not reactive, so mask editors bump a revision counter and libraries replace mask objects on save; keep that pattern when adding new mask surfaces.
- Canvas transforms live in `editor.scaleCanvas`, `resizeCanvas`, `cropCanvasTo`, `cropToContent`, and `cropToSelection`. They transform every layer's cels (including reference layers), change `doc.width`/`height`, clear the pixel selection, and bump `structureRevision` + `revision`. They are undoable via `pushHistory`; do not transform only the active frame.
- `canvas.ts` holds the pure pixel helpers: `scalePixelsNearest`, `resizePixels`, and `contentBoundsOf`. `contentBoundsOf` scans all frames and normal layers and ignores `role: "reference"` layers; reference-board images are not part of the document composite and are never transformed.
- `MenuBar.svelte` lazily computes Crop to Content/Selection availability only while the Project menu is open, because content bounds are a full document scan. Keep that behavior instead of evaluating it on every menu-bar render.
- Pixel edits use `editor.pushHistoryCel(layerId, frame)` and structural edits use `editor.pushHistory()`. Do not use `pushHistory()` for a brush stroke: it clones every layer and frame. `pushHistoryCels` records several cels at once (for example, clearing a frame).
- Every history entry carries a label and optional detail for the history dialog (`Edit → History…`, command `edit.history`, state `editor.historyOpen`). Pass a user-facing label to `pushHistory(label)`, `pushHistoryCel(layerId, frame, label)`, and `pushHistoryCels(patches, label)` when adding a new undoable action; cel entries derive their layer/frame detail automatically. `editor.historyRows` lists states oldest-first, including the base row and redoable steps, and `editor.jumpToHistory(position)` reaches one by stepping the normal undo/redo path. Do not apply stored entries directly outside `undo()`/`redo()`.
- `compositeFrameCached(doc, frame, revision, includeReferences)` memoizes up to eight frame variants and returns a shared read-only buffer. It defaults to excluding reference layers so export/preview paths are safe. `CanvasStage` passes `true` for the viewport; `Preview`, `ExportDialog`, and export encoders use the default. Use `compositeFrame` when a caller may need to own or mutate the buffer.
- `render.ts` reuses a scratch canvas/ImageData and exposes `drawPixels`, `drawScaled`, and `drawThumbnail`. Do not allocate a new canvas per draw.
- Reference layers are ordinary `Layer` values with `role: "reference"`, locked by default. They participate in the viewport composite and are skipped by `clearLayer`/`clearFrame`, drawing guards, and all export paths. Added/imported frames copy the current reference-layer cel so static references persist.
- Reference-board images live in `doc.references`, not in `doc.layers` or cels. They are rendered as separate `<img>` elements in `CanvasStage` and never enter `compositeFrame`/`compositePixel` or export. Store original compressed bytes and display bounds; image bytes are immutable and shared across history snapshots.
- Reference-board moves, zoom, rotation, opacity, visibility, and lock changes must not call `editor.touch()` or increment `revision`; they do not change the pixel composite. Add/remove operations use `pushHistory`. The panel edits zoom as a percentage of the natural image size through `setReferenceZoom`; display width/height remain the stored document-pixel bounds.
- `CanvasStage` coalesces sprite, overlay, and mirror draws into `requestAnimationFrame`. Keep that behavior when adding render paths.
- `CanvasStage.svelte` renders composited sprite pixels on the main canvas and selection/lasso visuals on a separate transparent overlay canvas. Keep the sprite effect limited to pixel/zoom dependencies; selection and lasso changes must not trigger `compositeFrameCached()` or a full sprite redraw. Onion skins use a third canvas below the main canvas, tinted per direction and hidden during playback.
- Frames own one cel per drawable layer: `layer.cels[frameIndex]`. Group nodes (`isGroup: true`) have an empty `cels` array and no pixels of their own. Adding/removing frames must update every non-group layer's `cels` array in lockstep with `doc.frames` (skip groups). Frame order changes must apply the same permutation to `doc.frames` and every non-group layer's `cels`.
- The layer stack is a tree stored as a flat, bottom-to-top `doc.layers` array: a group node is immediately followed by its children (contiguous), and `parentId` links a node to its parent group (missing means top-level). Use `isGroupLayer(layer)`, `buildLayerTree`, `flattenLayersTopFirst`, and `subtreeRange`/`siblingBlocks` (in `editor.svelte.ts`) instead of assuming a flat list. Compositing is recursive: `compositeFrame`/`compositePixel` composite each group's children into an offscreen buffer, then blend that buffer with the group's own opacity, `blendMode`, and `clipping`. `hasCompositeFeatures(doc)` detects grouped/blended/clipped documents so `compositeFrameCachedIncremental` falls back to a full composite (the flat prefix fast path is only valid for plain, normal-blend, non-clipped stacks). Blend math lives in `blend.ts` (`blendPixelPacked`, `BLEND_MODES`, `normalizeBlendMode`).
- `Frame` also carries optional `duration` (ms) and `tag`; `PixelDoc` carries optional `animationMode`/`animationLoop`. Contiguous equal tags render as a tag range in the timeline. Keep these fields in `cloneDoc`, history, project files, and autosaves.
- `frameSelection` and the shift-click anchor are per-project and must be included in `ProjectSnapshot`, `#syncActiveProject`, and `#activateProject`. `layerSelection` and its anchor follow the same rules. Restored ids are filtered against the active document.

## Commands and shortcuts

- `lib/editor/commands.ts` is the single source of truth for global actions. Add a `CommandDef` there when introducing a user-facing action; the command palette, shortcut editor, and keyboard handler all read it.
- Commands may have `enabled()` (hidden from the palette and skipped by the key handler when false), `ignoreRepeat` (for toggles such as playback), and extra `keywords` for search.
- `lib/editor/keybindings.svelte.ts` owns the reactive `bindings` map, combo normalization (`mod` matches Ctrl or Cmd), formatting, conflict detection, and localStorage persistence under `pixel-spell-keybindings`.
- Defaults live on the command definition as normalized combos (`"mod+shift+z"`, `"shift+g"`, `"alt+left"`, `"["`, `"space"`). A command can have several defaults (redo uses `Ctrl+Shift+Z` and `Ctrl+Y`).
- `App.svelte` resolves every global keydown through `keybindings.commandForCombo`; do not add hardcoded shortcut branches there. Tool shortcuts are commands too (`tool.<id>`). Tool commands stay enabled even when a tool is hidden, so its shortcut and command palette entry can still select it.
- The shortcut editor captures keys on `window` in the capture phase and stops immediate propagation so the app handler and dialog Escape handling do not run while rebinding. It rejects conflicts and supports up to three bindings per command.
- Restoring defaults replaces the map and removes the localStorage record.
- `App.svelte` prevents the browser context menu globally with `oncontextmenucapture`. App-specific context menus still receive the event; they just must not rely on the native menu.

## Projects and tabs

- The workspace holds multiple projects. `editor.projects` is a `$state<ProjectTab[]>` of tab metadata (`id`, `name`, `dirty`, `modified`); `editor.activeProjectId` selects one.
- The active project's live state lives in the top-level `editor` fields: `doc`, `activeLayerId`, `activeFrame`, `activeReferenceId`, `zoom`, `panX`, `panY`, `name`, `dirty`, `modified`, the undo/redo arrays, and counts.
- Inactive project state is stored in the private `#states` map as a `ProjectSnapshot` (doc, active layer/frame/reference, zoom, pan, undo/redo).
- Before switching, creating, opening, or saving, `#syncActiveProject()` copies live state into the active tab/snapshot. `#activateProject(id)` loads a target snapshot and tab metadata into the live fields.
- UI should use `projectName(id)`, `isProjectDirty(id)`, and `isProjectModified(id)`. They return live values for the active project and stored values for inactive tabs.
- Double-clicking a tab name edits it inline. `startRename` selects the tab first, then swaps the tab button for an input; Enter or blur calls `editor.renameProject`, Escape cancels. Renaming is not undoable but marks the project dirty/modified and updates the tab metadata so the name is saved with the project.
- `newProject(width, height, { name, background })` and `openProject(loaded)` add a tab and activate it. `background` is `transparent`, `white`, or `black`; opaque backgrounds fill the initial layer and name it `Background`. `closeProject(id)` removes a tab; closing the last project creates a new `Untitled` project. Closing the only never-modified project is a no-op.
- `dirty` means unsaved changes (tab dot + close confirmation). `modified` means the project has ever been touched, loaded, or saved (controls whether the single-project close button is enabled).
- Undo/redo, zoom, pan, rotation, active layer/frame, and the document are per project. Tool, tool strip order/visibility, color, palette collection, theme, grid, preview visibility, and timeline height are workspace-wide.
- `ProjectTabs.svelte` owns the tab strip and the unsaved-close `Dialog`. The close button is disabled when `projects.length === 1 && !isProjectModified(id)`.
- **File → New project** and **File → Open project** create tabs; **File → Save project** saves the active project. The menu bar no longer shows the document name — the active tab does.

## Import destinations

`ImportDialog.svelte` offers every valid destination for a dropped or picked file. `ImportTabId` is `project | layer | frames | reference-layer | reference-board | palette`.

- **Project** creates a new tab from the cropped `ImportProjectData` pixels.
- **Layer** creates a normal layer on the active frame with `importImageLayer`; the image is top-left cropped to the canvas.
- **Frames** inserts a new frame after the active frame with `importImageFrame`; it writes into a normal unlocked layer, creating one if needed.
- **Reference Layer** uses `ImportReferenceData.pixels` (the complete image fitted to `MAX_IMPORT_DIMENSION`, never cropped) and `importReferenceLayer`, with an "apply to all frames" option.
- **Reference Board** uses the original compressed bytes and `addReferenceImage`.
- **Palette** keeps the existing palette collection behavior.
- Board imports also have a direct file-picker button outside the dialog. It must revoke the analysis preview object URL after use.
- **File → Import from URL…** opens the dialog with no file. `analyzeImportUrl` downloads the link, derives an extension from the response type, magic bytes, or URL, and then reuses `analyzeImportFile`, so URL imports support every destination above. Cross-origin hosts must allow CORS; `analyzeImportUrl` returns a readable error instead of a partial import.
- Pasting an image file from the OS clipboard opens the dialog with that file. The window `paste` handler in `App.svelte` prefers a clipboard image, then falls back to `editor.pasteSelection()`. Commands that need the native paste event set `deferToPasteEvent` (see `edit.paste-selection`) so the keydown handler leaves the default action alone.

## Pixel format

Pixels are packed little-endian RGBA:

```ts
(a << 24) | (b << 16) | (g << 8) | r
```

- Transparent = `0`.
- Use `packColor(hex, alpha)` and `unpackColor(value)` from `color.ts`; do not hand-roll bit shifts elsewhere.
- `compositeFrame(doc, frameIndex)` flattens visible layers into a new `Uint32Array`.
- `pixelsToImageData` writes a cel/buffer directly into `ImageData` via a `Uint32Array` view. Keep this path intact for performance.

## Drawing pipeline

`CanvasStage.svelte` owns pointer handling:

1. Convert pointer coordinates to document pixels with `pixelFromEvent` (uses the canvas `getBoundingClientRect`, not zoom math).
2. On pointer down: guard against hidden/locked layers, push history, snapshot the active cel for shape preview.
3. Freehand tools paint through `paintBrush` (applies size and X/Y symmetry).
4. Shape tools restore the backup cel on each move and redraw from the start point, so the preview is non-destructive until pointer up.
5. Fill and eyedropper are single-click operations; the gradient tool previews from a backup cel while dragging.
6. Every pixel change calls `editor.touch()`.

When adding a tool:

1. Add its id to `ToolId` in `types.ts`.
2. Add metadata to `TOOLS` in `tools.ts` and map its shortcut. New tools default to visible; set `enabledByDefault: false` if it should start hidden. `toolLayout` appends new ids to the saved strip order automatically.
3. Add an icon branch in `ToolIcon.svelte`.
4. Add pointer behavior in `CanvasStage.svelte`.
5. Add its options in `ToolOptions.svelte`.
6. Add a shortcut row in `ShortcutsDialog.svelte`.
7. Update the README shortcut table.

## UI conventions

- Use existing shadcn-svelte components from `$lib/components/ui/*`; do not introduce a second component library.
- Import Lucide icons from deep paths, e.g. `import Pencil from "@lucide/svelte/icons/pencil";`.
- Svelte 5 syntax only: `$props()`, `$state`, `$derived`, `$effect`, `onclick` (not `on:click`), snippets with `{#snippet}`/`{@render}`.
- Import local TS modules with `.js` extensions (`./doc.js`, `$lib/utils.js`) and `.svelte` components with their full filename.
- The visual language is a clean, modern app UI — not pixel-art chrome. Use shadcn tokens (`bg-background`, `text-muted-foreground`, `border`, `ring`, etc.) rather than hard-coded colors. The only intentionally pixel-flavored elements are the canvas checkerboard and the logo mark.
- Keep panel headers at `h-11` and icon buttons compact (`size="icon-xs"`/`icon-sm`) to preserve the layout.
- The `Slider` component requires `type="single"` (bits-ui does not infer it). Use `type="single"` for all single-value sliders.
- Tooltips on the tool strip are required; new tool buttons should follow the same `Tooltip.Root` + `Trigger` + `Content` pattern.

## Timeline and resizing

- The timeline is a single table, not separate layers/frames panels:
  - Rows are layers (and groups), displayed top-to-bottom via `editor.timelineLayers` (`flattenLayersTopFirst`), which expands the tree and honors each group's collapse state. Each `LayerRow` carries `layer`, `depth`, and `last` (last child of its parent). `TimelineLayerRow` indents rows by `depth * LAYER_INDENT` and draws IDE-style vertical guide lines at every nesting level (inset from the row borders); `LAYER_INDENT` is exported from the component's module script. `TimelinePanel` widens the layer column by one indent per level through the `--layer-col-width` CSS variable, which the sticky header and row headers share. The Layers header cell has no label: its eye button hides every layer when any layer is visible and shows them all otherwise, its lock button locks every layer and group when any is unlocked and unlocks them all otherwise, and its link button links new cels on every layer when any layer is continuous and stops linking them otherwise. Group rows carry only their collapse chevron plus their own visibility and lock toggles, and all three columns (global, layer, group) share the same icon size, gap, and left inset so the controls line up vertically. Both toggles cascade to every layer and nested group inside it (reference layers stay locked). The group row's empty frame area holds its effect blocks plus a trailing funnel-plus button; block drag/drop is local to `TimelineLayerRow` (`effectDragId`/`effectDrop`) and must stop propagation so it never starts a layer drag or triggers the row's layer drop handlers.
  - Columns are animation frames, plus a trailing add-frame column and a filler column that absorbs extra width.
  - A tag row sits above the frame numbers. Contiguous frames with the same `tag` render as one `colspan` range; clicking a range selects it, and double-clicking opens frame properties.
  - Clicking a cel selects its layer and frame; dragging across cels selects a rectangular block of layers and frames, with the last cel becoming the active cel shown on the canvas. Shift-click on a cel extends both the layer and frame ranges. Clicking a frame header selects only the frame; clicking a layer header selects only the layer (Shift extends either range). Ctrl/Cmd-click does not toggle timeline selections, so frames and layers stay contiguous. The active cel uses a 2 px `border-primary` border (no ring), and every cel in a selected row or column uses the `bg-primary/15` background class.
  - Double-clicking a layer header opens `LayerPropertiesDialog` for that layer, and right-clicking it opens a layer action menu. Frame headers keep double-click for `FramePropertiesDialog` and right-click for frame actions. Right-clicking a cel shows the layer actions and frame actions together, separated by a divider.
  - Dragging frame headers reorders the selected range. The drag payload moves `doc.frames` and every layer's `cels` with the same permutation. Right-clicking a frame header opens the frame action menu; right-clicking a cel opens the combined layer and frame action menu for Link cels/Unlink cels, copy/paste, duplicate, move, duration/tag, delete, and layer operations. Link and unlink act on the whole selected frame range for every selected layer; Link is disabled when only one frame is selected, while Unlink also works on a single cel.
  - Dragging a layer header reorders it via `editor.moveLayerTo(id, spec)`. The drop spec is `before`/`after` (sibling of the reference node) or `into` (last child of a group); `TimelineLayerRow` splits each row into before/after/into zones from the pointer's Y position and the panel rejects dropping a node onto itself or its own descendants via `editor.layerSubtreeIds`.
  - The header row and the layer column are sticky (`position: sticky`) inside an `overflow-auto` container. Keep `border-separate border-spacing-0` and opaque header backgrounds, or scrolled content will show through. The tag row sticks at `top-0` (24 px); the frame-number row sticks at `top-6`.
  - The active frame header and selected frames both use `bg-primary/15` while keeping the default muted frame-number text color, so the text does not change when a frame becomes active. Selected layer headers (including the active layer) use `bg-primary/15`; unselected layer colors still tint their header. Cels in a selected row or column get `bg-primary/15`, and the active cel uses a 2 px primary border instead of the former border+ring combo.
  - Layer opacity is edited in `LayerPropertiesDialog` (the dialog stages the value and applies it with the rest of the layer settings). Layer operations act on `layerSelection`: `groupSelectedLayers()` wraps every selected root (a nested selection collapses to its topmost selected ancestor) in a new group at the topmost selection, `outdentSelectedLayers()` moves each selected layer one level out of its group, and `deleteSelectedLayers()` deletes selected layers while dissolving selected groups and promoting their children. `canDeleteSelectedLayers` requires at least one non-group layer to remain, and `canOutdentSelectedLayers` drives the ungroup button's enabled state.
  - The plus button after the last frame column and the toolbar's add-frame button both call `editor.addFrame()`, which appends the new frame at the end of the timeline and makes it active. A matching plus and folder-plus pair sit below the last layer header and call `editor.addLayer()` / `editor.addGroup()`. Both add the new node at the bottom of the stack (index 0 of the flat list), which is the bottom row of the timeline.
  - The onion button and its dropdown control `onionEnabled`, previous/next visibility, range, opacity, and tint presets. The animation-mode menu and loop toggle sit to the right of the FPS field; mode cycles forward, backward, and ping-pong, and loop decides whether playback repeats or stops after one pass.
  - Frame durations default to `1000 / doc.fps` when `Frame.duration` is missing. `FramePropertiesDialog` and `DuplicateFramesDialog` back the right-click actions; duplicate offsets shift every cel and clip at the canvas edges.
  - Playback uses recursive `setTimeout` with `frameDurationAt()` and `nextPlaybackFrame()` so per-frame durations, selection-based animation ranges, mode, and loop are honored. Do not replace it with a fixed `setInterval`.
- `TimelineDock.svelte` owns the split between canvas and timeline:
  - Height is local `$state`, clamped to 180 px minimum and `window.innerHeight - 44 - 140` maximum.
  - Persisted in `localStorage` under `pixel-spell-timeline-height`.
  - The divider is a focusable `role="separator"` with pointer capture. Dragging up grows the timeline; `↑`/`↓` resize by 16 px (48 px with Shift), `Home`/`End` jump to the limits.
  - The divider is intentionally a `div` with `tabindex="0"`; Svelte's a11y warnings are suppressed for this ARIA window-splitter pattern.

## Layout contract

The shell is intentionally:

```
Menu bar (File/Edit/Project/View/Help menus left, canvas/frame/layer readout centered, display toggles right)
├── Tool strip (left, thin, square buttons + tooltips)
├── Left panel (tool options on top, color slots/palette below; two equal-height halves that scroll independently)
└── Main area
    ├── Project tab strip (project tabs, dirty dots, close buttons, new-project)
    ├── Canvas (fit/rotation/zoom controls bottom right, grid controls bottom left, cursor, Reference Board panel/button top-left, Preview window/scan-eye button top-right)

    └── Timeline (Aseprite-style table: layer rows × frame columns, sticky headers, cel thumbnails, add-layer row)
```

Preserve these regions and their relative placement when making changes.

## Persistence and files

- Project files use the `.pixelspell` extension and the current binary `PXSP` container (version 5). The header stores dimensions, fps, frame/layer counts, and a UTF-8 metadata block (name, palette, active frame/layer, per-frame duration/tag records, animation mode/loop, layer flags including `role` and group effect stacks). Each cel is stored as raw little-endian RGBA or RLE, whichever is smaller. A self-describing reference-board section follows the cels: metadata JSON plus each image's original compressed bytes.
- `serializeProject` returns a `Uint8Array`; `parseProject` accepts a `Uint8Array`/`ArrayBuffer`. `readProjectFile` reads `arrayBuffer()`. Invalid files return `null` and the UI alerts the user. Opening a project does not replace the workspace palette collection.
- Older unreleased `PXSP` versions are intentionally rejected; bump `FORMAT_VERSION` whenever the container changes. Reference-board images are limited to 64 MB each, 64 images per project, and 256 MB total.
- Parsing enforces 1–2048 px per side, at most 1024 layers, at most 1000 frames, a 512 MB cel budget, and a 256-color palette. Duplicate layer ids are regenerated so lookups stay unambiguous. Saving throws if a project exceeds the layer/frame limits.
- Layer visibility, opacity, and lock state are serialized with each layer. Missing boolean fields default to visible and unlocked. An optional `layer.color` (`#rrggbb`) is serialized in the same metadata block as a timeline identity tint; it is presentation-only, is not undoable, and never affects compositing, previews, or export.
- `editor.setLayerColor(id, color | null)` normalizes the color through `layer-color.ts`, marks the project dirty, and deliberately avoids `touch()`/`revision` because the composite is unchanged. `TimelineLayerRow` shades the header and the whole frame track through `layerTint`, while `MenuBar` shows the active layer's color dot. The timeline toolbar's **Layer properties** gear opens `LayerPropertiesDialog`, which stages the layer name, opacity, color, blend mode, and clipping and applies them together; the row itself has no color control.
- Opening a project file creates a new tab; saving applies to the active project only.
- Image export uses `canvas.toBlob`; sprite sheets support horizontal, vertical, and grid layouts. PNG image and sheet export can instead use `encodeGrayscalePng` for a true single-channel 8-bit grayscale file (color type 4 when the background is transparent). Grayscale always uses perceptual luminance, never an RGB average. Sprite-sheet metadata is generated by the pure `sheetMetadata()` path in `export.ts` (Aseprite, TexturePacker JSON Hash, or Godot JSON) from the same geometry as the image, so frame rects, spacing, scale, trim, pivot, and tag animations stay in sync. All metadata rectangles are in output-sheet pixels. Trim scans visible normal layers and ignores reference layers. The export dialog downloads the JSON sidecar as a second file shortly after the sheet.
- `editor.saveToFile()` triggers a browser download and clears the dirty flag.
- Dirty projects are also serialized to IndexedDB by `autosave.ts` (database `pixel-spell-autosave`, store `projects`) so a crash can be recovered. `editor.autosaveNow()` snapshots the active tab; `#syncActiveProject` snapshots the outgoing tab on switch, and `autosaveAll()` covers inactive tabs after a restore. Saving or closing a dirty tab deletes its record. The recovery dialog parses the stored `PXSP` bytes and previews the active frame.

## Gotchas

- Vite HMR re-evaluates the state module and resets the in-memory document. This is expected during development; do not treat it as a bug.
- Project tabs are in-memory, but dirty tabs are mirrored to IndexedDB for crash recovery. A reload offers to restore them through `RecoveryDialog.svelte`; clean tabs are not autosaved.
- Autosave work must never mark a project dirty or change its revision. Serialization comes from `serializeProject`, so it shares the project file limits and skips documents that cannot be encoded.
- Recovery records are keyed by project tab id. Delete the record when a project is saved or closed, and clear all records when the user restores or discards. The restore path reopens tabs with `openProject(project, { dirty: true })`.
- Always sync the active project before switching, creating, opening, or saving. The live top-level fields are not automatically mirrored into the inactive snapshot map.
- The tab bar must use `projectName`/`isProjectDirty`/`isProjectModified`; the active tab's values are live, inactive tabs use stored metadata.
- Closing the only never-modified project is a no-op; closing the last remaining project creates a new `Untitled` project.
- `setPointerCapture` is wrapped in `try/catch` so synthetic pointer events (used in automated browser checks) do not throw.
- The file input in `MenuBar.svelte` is hidden. It is opened via `File → Open project…`.
- `$effect` in `TimelinePanel.svelte` drives playback with a recursive `setTimeout` (so per-frame durations, selection-based ranges, animation mode, and loop are honored); it depends on `editor.playing`, `editor.doc.fps`, `editor.doc.animationMode`, `editor.doc.animationLoop`, `editor.frameSelection`, and `editor.doc.frames.length`. If you add playback features, keep cleanup in the effect return.
- The canvas stage is a fixed viewport (no native scrollbars). The sprite is absolutely positioned at the stage center, rotated by `editor.rotation`, and translated by `editor.panX`/`editor.panY`, so panning and rotation work at every zoom level. Pointer coordinates are mapped through the inverse rotation into canvas-local space, so drawing works at every rotation. Middle-mouse drag pans regardless of the active tool. Pan is clamped using the rotated bounding box so at least one sprite pixel stays visible, and a resize or rotation that invalidates the pan recenters the view. Fit zoom accounts for rotation. Zooming moves the view halfway from the current center toward the pointer. The grid uses `editor.gridSize` (1–64 document pixels per cell) and is only drawn when a cell is at least 6 screen pixels. Mirror guides are drawn on a stage-sized overlay, rotate with the canvas, and can be dragged from anywhere on the stage, not just the canvas. Mirror toggles/positions intentionally do **not** increment `revision`; the mirror overlay effect tracks the mirror state directly. Radial symmetry shares that overlay: it stores its center as an offset from the document center, draws red spoke guides plus a draggable center handle in red, and can be combined with the axis mirrors. Disabling it resets the center. `CanvasStage` snapshots both the mirror axes and the radial settings once per stroke.
- `CanvasStage` caches the stage bounding rect in `stageRect` (updated by its `ResizeObserver`) instead of calling `getBoundingClientRect()` for every pointer event.
- `editor.touch()` invalidates `compositeFrameCached`; changes that do not affect pixels (pan, zoom, rotation, mirror guides) must not call it. `editor.selectLayer`/`selectFrame` also do not invalidate pixels.
- Canvas scale/resize/crop must transform every layer's entire `cels` array in one pass and then update `doc.width`/`height`. Clear `selection`/`selectionRevision` because the old mask no longer matches the new dimensions. Reference-board images are independent `<img>` overlays and keep their coordinates; reference layers are cels and must be transformed.
- Crop to Content uses `contentBoundsOf`, which intentionally ignores reference layers and board images. Crop to Selection uses the selection mask bounds, even when the selected region is transparent. Both return false when the requested rectangle is already the full canvas, and the Project menu disables them in that case. Crop to Content is also disabled when there is no painted content.
- The Project menu recomputes crop availability in a `requestAnimationFrame` only while open. Do not turn `findContentBounds()` into a getter that runs on every menu-bar render or every brush stamp.
- The timeline context menu is a fixed-position custom menu (`data-timeline-menu`), not a shadcn dropdown. It has `frame`, `layer`, and `cel` variants; the cel variant renders layer actions, a divider, then frame actions. It closes on outside `pointerdown` and Escape. Cel selection happens on `pointerdown` so a drag can extend the layer+frame block; a cel `click` only handles keyboard activation (`event.detail === 0`). Frame actions operate on `frameSelection`, so right-clicking an unselected frame selects it first, while right-clicking a selected frame preserves the range. `App.svelte` ignores global shortcuts whose target is inside `[role="menu"]`.
- The cel drag anchor lives in `TimelinePanel.svelte` (`celDrag`), while the selection anchors live in the editor. `pointerenter` on each cel cell extends the block only while `celDrag` is set; `pointerup`/`pointercancel` on `window` clears it. Layer row controls carry `data-layer-control` so clicks on eye/lock/collapse do not select the row.
- The temporal frame clipboard (`#frameClipboard`) is separate from the pixel clipboard and is shared across project tabs. It stores one cel per layer id plus duration/tag; pasting into a project with different layer ids fills missing cels with transparent buffers.
- GIF export uses `animationFrameIndices(doc, frames)`; explicit frame durations override the dialog's fallback FPS. Keep palette collection and the frame loop on the same index list or an export will build a palette from frames it never writes.
- Onion-skin state is not part of project files or history. `CanvasStage` hides onion skins while playing and redraws them on `activeFrame`, `structureRevision`, `historyActionRevision`, `layerAppearanceRevision`, and zoom—but not on every `revision` bump.
- The timeline table uses sticky `<th>` cells inside an `overflow-auto` container. Keep `border-separate border-spacing-0`, explicit column widths, and opaque header backgrounds; otherwise scrolling content shows through or columns shift.
- Timeline height is a UI preference stored in `localStorage`, not part of project files.
- Custom palettes are workspace preferences stored in `localStorage` under `pixel-spell-palettes`; the built-in palette always has id `default` and is never persisted or editable. Custom palettes are capped at 256 colors and new ones start empty. Each custom palette stores its original add/import order and last sort mode so the palette tools menu can restore **Original order** after sorting by hue, saturation, or lightness. `ColorPanel.svelte` drags swatches into the gap before another swatch through `editor.movePaletteColor(from, insertAt)`, which uses the pure `reorderPaletteColor` helper and makes the manual arrangement the new `originalColors` order with `sortMode: "original"`. The swatch grid (not the whole panel) owns the scroll area and keeps padding around it so the hover-scaled swatches are never clipped. The Palette Library dialog adds library entries through `importPalette`, which creates a normal editable palette; adding the same entry again creates an independent copy with a suffixed name.
- `editor.paletteLocked` and the active palette id are persisted with the palette collection. `paletteEditable` means the active palette is custom and unlocked; use it for add/remove/rename/delete/sort/dedupe/ramp controls. The `+` button appends `primaryColor` even when the palette already contains it; duplicates are persisted, and **Remove duplicates** cleans them up. Locking constrains color choice only: `snapColorToPalette` runs on picker release (SV pointer up, hue/channel `change`, hex commit) and `setColorFromPacked` snaps eyedropper picks to the nearest palette entry using OKLab distance. Existing pixels are never rewritten.
- `editor.paletteCycleStart`, `paletteCycleEnd`, `paletteCycleMs`, and `paletteCycleDirection` describe the workspace-level Color Cycles range and motion. They are intentionally **not** stored in project files, history, or autosaves; opening a project keeps the current workspace cycle settings. Swatch clicks only set colors and never select a range.
- Color cycling lives entirely in `ColorCyclesDialog.svelte`, opened from the palette tools menu or the **Color cycles…** command. The dialog owns the preview phase and timer, renders its own composited frame preview with `buildPaletteCycleMap` + `remapPalettePixels`, and shows the rotated range strip. `CanvasStage`, `Preview`, thumbnails, onion skins, and export never apply a cycle remap.
- `editor.bakePaletteCycle(shift)` writes one phase into the active frame's visible normal layers (reference layers are skipped) and is undoable via `pushHistoryCels`. `editor.generatePaletteCycleAnimation({ steps, durationMs, tag })` inserts one full pass after the active frame, rotates each copy, and selects the generated frames so they become the animation range. Generated frames are ordinary frames with `duration`/`tag`, so GIF and sprite-sheet export animate them without any fresh file-format fields.
- `paletteCyclePeriod(length, direction)` is the number of steps in one pass (`2 × length - 2` for ping-pong). Clamp generated step counts and phase sliders to it.
- Ramp generation is pure (`palette-ramp.ts`) and appends through `editor.addPaletteRamp(colors, lockAfter)`. Ramps always target the active palette, skip duplicates and the 256-color cap, reset `sortMode` to `original` so the ramp stays contiguous, and may set `paletteLocked` when done. The built-in palette remains read-only.
- Palette analysis is pure (`palette-analysis.ts`): `unusedPaletteColors(doc, colors)` returns entries no normal layer uses in any frame (reference layers skipped, early exit once every color is found), and `analyzePaletteCoverage(doc, colors)` builds the coverage report. `editor.removeUnusedPaletteColors()` refuses the built-in and locked palettes, filters both `colors` and `originalColors`, re-sorts when a sort mode is active, and persists. The coverage dialog is read-only and recomputes from `editor.revision`, so it also works for the Default palette.
- Layer visibility/opacity are document-wide. Per-frame visibility would require a model change and UI work.
- Reference layers cannot be unlocked or drawn on. `selectLayer` allows selecting them for visibility/opacity/rename/reorder/delete, but `editor.activeLayerDrawable` returns false. `clearLayer` and `clearFrame` skip them. `addFrame` and `importImageFrame` copy the current reference-layer cel so a static reference persists.
- Reference-board images are separate from the cel composite. Do not add them to `compositeFrame`; `ReferenceBoardImage.svelte` draws each one with a component-local blob URL and applies position/size/opacity/rotation. The panel's active reference is the only one that can be dragged on the stage, and only while unlocked.
- Board reference bytes are immutable and shared by `cloneDoc` history snapshots. Never mutate `reference.bytes` in place; replace the array if the source changes. `ReferenceBoardImage.svelte` and `ReferenceThumb.svelte` create and revoke their own object URLs.
- Reference-board changes do not increment `revision`; they only set `dirty`/`modified`. Add/remove uses `pushHistory`; move/zoom/rotation/opacity changes are intentionally not undoable. Stage hit-testing inverse-rotates the pointer around each board image's center before testing its local bounds.
- `ImportReferenceData.pixels` is the entire source image fitted to `MAX_IMPORT_DIMENSION`, not the top-left crop used by project import. Reference-board imports use the original compressed bytes instead.

## Definition of done

- `npm run check` passes with zero errors/warnings.
- `npm run build` succeeds.
- `npm run bench` completes without assertion failures (it also verifies project round-trips).
- Drawing, erasing, fill, gradients, shapes, eyedropper, undo/redo, layer operations, lock toggling, frame operations, playback, cel selection, and timeline resizing still work.
- Import destinations work for images: project, layer, frame, reference layer, and reference board; palettes still import. Reference layers are locked and non-exported; board references are independent of frames/layers, can be moved outside the canvas, and are embedded in saved projects.
- Project tabs switch correctly with independent documents, undo history, zoom, active reference selection, frame selection, and dirty state; closing a dirty project confirms first. Double-clicking a tab name renames it inline, marks it dirty, and the new name survives save/open and project switches.
- Onion skinning shows previous/next frames behind the active frame, respects the range/opacity/tint controls, toggles with `O`, and stays hidden during playback.
- Frame tags render as ranges, durations override the project FPS, two or more selected frames drive playback and animation export, and the animation-mode/loop controls behave forward, backward, and ping-pong. Frame reordering, multi-frame selection, copy/paste, duplicate-with-offset, and the right-click menu all update every layer's cels in lockstep.
- Scale Canvas resamples every cel nearest-neighbor, Resize Canvas crops/extends around the chosen anchor with transparent new pixels, Crop to Content trims all transparent borders across layers and frames, and Crop to Selection uses the selection bounds. Each operation is undoable and clears the selection.
- Autosave recovery survives a reload: a dirty project is offered with a preview, Restore reopens it as an unsaved tab, and Discard removes the snapshot. Saving a project removes its autosave.
- Color cycles open from the palette tools menu, preview only inside the dialog, bake one phase into the active frame, and generate a full loop of tagged frames with explicit durations that GIF/sprite-sheet export honors. Cycle settings are not written to project files.
- Closing the last project creates a new `Untitled` project, and the only never-modified project's close button is disabled.
- The timeline table keeps its sticky header row and layer column while scrolling, and the divider respects its min/max bounds.
- New UI matches the existing modern shadcn aesthetic and respects the layout contract.
- Update `README.md` when user-facing behavior or shortcuts change.
